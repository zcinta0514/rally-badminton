# P0-1／P0-2 场景与对照规格

本文件定义可执行的比较方法；当前完成状态以 [PROJECT-STATUS.md](PROJECT-STATUS.md) 为准。通过脚本检查表示输入和证据可复现，不表示新打球系统、动作、表面或手机体验通过。

## 基线保护与证据层次

- Git 基线和未提交源码、候选资产、原始数据已保存在 `artifacts/execution-prep/20260930/`；P0 开工前补充状态快照见 `artifacts/p0/baseline/`。恢复时在空目录解包，按指纹比较后整合，不能覆盖正在工作的目录。
- 正式人物仍为 `src/models/athlete.glb`。本阶段只增加独立实验入口、场景采样和规格，正式三球种、输入和联机协议不由此切换。
- 旧表面失败索引固定在 `shared/p0-regressions.js`。31 个失败样本来自 77 个旧 Three.js 姿态，关联 GLB、源码、原报告和真实世界空间几何的 SHA256；这里的旧 `passed: false` 永远不是新候选的质量通过条件。
- 失败帧必须按 `replayOrder` 预热，再按原始 60 Hz 顺序采样。原控制器的 `reset` 不保证清除全部先前历史；单帧跳转不能代替复现。平抽原时间有 5 秒偏移，而状态内时间是周期内时间，采样帧以样本 ID 的末尾帧号为准。
- `node scripts/check-p0-regressions.js` 只读重建全部失败姿态的最终几何并与旧指纹严格比对；加 `--out artifacts/p0/<新的报告.json>` 可保存报告，已有证据拒绝覆盖。它沿用原穿插分类，不重新计算碰撞，也不证明未采样姿态无穿插。

## 可重复输入与真实球路

入口：`node scripts/run-p0.js --out artifacts/p0/<新的目录>`。目录已存在时拒绝执行，禁止静默改写基线。

输出每例的初始完整状态、逐 tick 双人输入、实际触球／结束事件、每 tick 完整状态、来源指纹和汇总。固定种子 `310930`、60 Hz 外层 tick；旧比赛逻辑内部仍用现有最多 1/120 秒分片和触球时刻细分。这里没有新建权威球拍求解器。

每例只在起点布置一次来球。此后球路、碰网、落地、得分、移动和击球均来自 `shared/game.js`，不在中途重置球或瞬移人物。球拍姿态来自现有 Three.js 适配，不能倒过来决定比分。

移动、准备、释放、停止、反向和再次启动的时间窗口在 `p0Schedule()` 中，以整数 tick 表示。平抽交换采用固定版本 `observed-intercept/v1` 控制器，只根据当下可观察球和现有预测器生成输入，双方走相同可达性门槛。**先录制后冻结实际输入**；保持旧状态形状的候选可调用 `replayP0(initialState, inputs, {step})` 回放这份固定输入，不能重新运行自适应控制器后声称输入相同。P2 新协议接入时还需显式转换初态、手势／意图和观测输出，记录适配器版本；当前回放器没有冒充可直接运行 `PlaySnapshot`。

## 五组脚本覆盖

共 48 例。除发球固定正手持拍外，每组均覆盖正反手侧来球、主动到位／延迟启动、近场／远场；后场杀球首批为正手，高远覆盖正反手。镜像会同步旋转人物、球、速度、服务区和输入，不能只换镜头。

| 组 | 初始条件和操作 | 可观察结果 | 候选的失败判据 |
| --- | --- | --- | --- |
| 发球（4 例） | 近／远场，各短发与长发；先准备再释放，发球后移动再停止 | 持球、引拍、真实触球、过网和对角区结果、发球后准备 | 持球与拍头漂移；无真实触球却出球；方向不匹配；随挥后不能准备下一拍 |
| 前场弓步（16 例） | 同来球和步法，分别请求网前控制／挑球；正反手，各主动／被动，两端 | 来球与人位置、承重、触球或漏接、出球差异、推地返回 | 穿地或脚滑；够不到却理想触球；两种意图无可解释区别；恢复无推地与平衡 |
| 后场高远／杀球（12 例） | 高远正反手，杀球正手；向后到位或延迟启动；准备、释放、制动、向前回位 | 触点高度、出球、转体、起落和停止；主动／被动结果差异 | 不到位也无代价杀球；仅甩手腕；落地／收拍穿身；没有合理制动或下一次启动 |
| 平抽连续交换（8 例） | 正反手侧起始来球，双方根据观测移动和释放，连续 15 秒、不补球 | 触球侧交替、每次出入速度、持拍高度、紧凑恢复、下一拍 | 少于 4 次连续触球；高远轨迹冒充平抽；长恢复锁死；正反手转换跳变 |
| 制动和回位（8 例） | 从横向速度起步，防守击球，零输入制动、反向移动、再次启动；延迟条件配相同节奏 | 速度与位置连续性、停止距离、转向、出球后位置、再次启动 | 瞬间掉头；足部滑行；靠瞬移或伸长手臂够球；恢复动画结束但失衡；回位辅助压过玩家输入 |

旧版实际使用的适配关系：控制→旧 drop，高球／低位防守→旧 clear，后场进攻→旧 smash；平抽暂用旧 clear 发起真实连续交换。此关系只用于对照，不是 P0-3 新接口的实现，也不是后续情境选择算法。反手标签说明来球相对身体的位置，旧共享状态尚不决定握拍技术。

首轮用例按可复现实验条件布置，不能声称是测得的专业球员速度或标准训练参数。极限高度、来球速度扫描、打断组合、完整杀球—防守接续将在后续 P2／P4 扩展；不得凭当前 48 例声称全覆盖。

## 统一验收口径

1. 脚本层：JSON 往返和冻结输入重放必须产生相同的完整状态与事件；无 NaN／Infinity；触球 ID 单调且不重复；镜像结果对应；初始状态和输入日志不被回放修改。
2. 球路层：记录实际触点、入射／出射速度、意图落点与预测终点、真实落地或碰网结果。接不到就保留漏接，不能为截图补造一次击球。
3. 动作层：先看 1×连续动作，再看慢放与逐帧。握拍、承重、制动、转向、回位和下一拍必须一起观察。旧状态缺少的朝向、支撑、平衡字段应标为未实现，不以画面推算值伪装权威状态。
4. 表面层：服装穿插超过 1 mm 失败；触球误差目标不超过 1 cm；支撑窗口鞋底漂移目标不超过 5 mm。漂移相对于支撑窗口开始的世界锚点测量，不能用每帧误差重置门槛。旧失败可以帮助验证检查器，不能作为候选可接受上限。
5. 渲染／网络层：回放模拟以 tick 为准，30／60／120 FPS 只改变读取哪些帧。渲染层自己仍要检查速度和过渡。P2 联机接入后须另外测延迟、重复消息、重连和回滚；P0 回放通过不能代替这些测试。

## 球场复现入口

运行本地服务后打开 `/src/p0-review.html`，不依赖首页的新功能开关。页面包含五组用例和旧失败帧，可播放、暂停、逐帧、倒带、选择两端用例及镜头。

- 画幅固定 960 × 540、像素比 1，使用原球场灯光；截图记录用例、tick、镜头和构建 ID。像素值可能受 GPU／浏览器影响，不以截图哈希作为跨设备图像质量门槛。
- 旧失败视图使用与原 Node 几何采样相同的候选更新顺序，不再叠加 CourtView 的另一轮 IK；球场、相机、球和材质仍在真实 Three.js 运行时呈现。
- 新场景使用真实共享状态和固定 60 Hz 姿态采样，漏接和恢复结果直接显示；未替代手机实际比赛验收。
- 源码改动后重启 Node 快照服务，核对 `/runtime-config.js`、关键脚本、GLB 和页面实际功能，确认无旧 Service Worker 控制。

P0-5 的手机型号、系统、浏览器、画质、热状态、双人连接条件仍需单独冻结；桌面固定画幅不是手机性能测试。
