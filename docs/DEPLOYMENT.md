# 运行与局域网对打

正式版提供**人机练习＋局域网好友 1V1**。局域网对打使用一台电脑运行游戏服务，
不需要公网服务器或域名。HTTPS 配置保留为可选的离线主屏幕方案，公网联机
不属于本版交付范围。

## 开始局域网对打

主机电脑安装 Node.js 22 或更新版本，在项目目录执行：

```sh
npm ci
npm start
```

1. 主机电脑和两位玩家连接同一 Wi-Fi，或支持设备互访的同一热点。
2. 主机启动后，终端会显示可供手机访问的局域网网址。两位玩家都打开**同一个网址**。
3. 房主选择角色和分制，点「好友对打」，填写昵称并创建房间。
4. 房主分享邀请链接或 **5 位房间码**。对方在同一局域网网址填写昵称和房间码后加入。
5. 两人到齐后自动开始；双方同意可再来一局。主机电脑和 `npm start` 服务全程保持运行。

主机本机可打开 `http://localhost:3000/`，手机应使用终端显示的局域网网址。
手机上的 `localhost` 指向手机自身。

**房间码必须在创建它的同一服务器网址使用。** 两台电脑各自启动的游戏服务拥有
不同房间，即使代码相同也不互通。主机停止或重启会清空房间，需要重新创建。
排行榜属于该服务器，使用默认数据文件时可在正常重启后保留。

## 从在线人机入口切换到局域网

GitHub Pages 的在线入口可以直接进行人机练习。点击「好友对打」，在局域网
入口对话框中粘贴主机电脑提供的局域网地址或邀请链接，即可跳转到完整游戏页面，
然后创建或加入房间。两位玩家最终使用的是同一个局域网网址。

GitHub Pages 本身仅托管静态网页，不运行房间服务。在线人机页面不能凭一个
局域网房间码找到主机；应先通过主机地址进入，再使用房间码，或直接打开房主
分享的局域网邀请链接。

## 无法打开或加入时

- 先确认两台手机都能打开主机显示的同一个局域网网址，再检查房间码。
- 主机电脑需保持开机，终端中的游戏服务不能关闭；地址变化后重新分享网址。
- 路由器或热点需允许设备互访。访客网络、AP 隔离或热点设备隔离可能阻止连接。
- 系统防火墙需允许 Node 接收当前网络的 TCP 3000 连接。
- 房间满员、主机重启或房主离开后，需要创建新房间并分享新码。

## 可选：HTTPS 与离线主屏幕

普通局域网 HTTP 即可运行人机和好友对打。完整离线缓存需要浏览器信任的 HTTPS
网址；可直接使用在线人机入口准备离线资源，也可按需配置自己的可信 HTTPS 入口。
离线缓存提供人机练习，好友对打仍需连接正在运行的主机服务。

仓库保留 `deploy/rally.env.example` 和 `deploy/nginx.conf.example` 作为配置示例。
自行配置 HTTPS 时，使用自己的地址和有效证书，把 Nginx 代理到同机 Node 服务，
并让 `ALLOWED_ORIGINS` 与实际页面来源一致。真实配置、私钥和证书不要提交 Git，
也不要放入 `src/`、`icons/` 等浏览器可下载的目录。

`npm start` 不会自动读取 `.env`。需要使用环境文件时，复制示例并设置实际值，
再运行 `node --env-file=.env server/index.js`。

| 配置 | 用途 |
| --- | --- |
| `HOST` | 直接局域网运行默认监听 `0.0.0.0`；Nginx 同机代理时可设为 `127.0.0.1` |
| `PORT=3000` | 主机游戏服务端口 |
| `ALLOWED_ORIGINS` | 可选 HTTPS 代理使用的完整网页来源，逗号分隔，不带结尾斜杠或通配符 |
| `ALLOW_MISSING_ORIGIN=0` | 只允许带有效来源的浏览器连接 |
| `LEADERBOARD_PATH` | 榜单 JSON 的持久存储位置，默认 `data/leaderboard.json` |
| `PUBLIC_WS_URL` | 默认留空，游戏连接当前页面所在的主机服务 |

iPhone 在 Safari 中打开可信 HTTPS 网址，通过分享菜单添加到主屏幕。首次联网
等到「离线人机已就绪」再断网。新版备好后，结束比赛并关闭全部游戏标签页与
主屏幕窗口，再打开启用；不会在对局中强制刷新。

## 静态人机页面的构建

执行 `npm ci` 和 `npm run build`，可导出 `dist/` 静态包。GitHub Pages 项目站点
使用子路径，仓库自带 `.github/workflows/pages.yml`。在仓库 Settings → Pages
选择 GitHub Actions 后，推送 `main` 会测试、构建并发布在线人机入口及局域网指引。
工作流只上传 `dist/`，不上传服务器数据或环境配置。

手动构建可在 shell 中设置以下配置后执行 `npm run build`：

```ini
PUBLIC_BASE_PATH=/rally-badminton/
PUBLIC_DEMO_MODE=1
PUBLIC_WS_URL=
```

默认路径是 `/`，子路径须以 `/` 开始和结束。`PUBLIC_DEMO_MODE=1` 提供静态人机
入口及局域网进入指引，不在静态页面中连接房间服务或加载排行榜。默认关闭时
保留完整局域网前端。Service Worker、manifest 和资源清单均限定当前应用路径。

## 数据与备份

榜单需要可写的持久磁盘。主机管理者可备份 `data/leaderboard.json`，不要上传
公开仓库。昵称和分数会出现在该服务器的榜单，匿名设备凭据不会公开。
当前没有跨服务器同步、注册账号或跨设备找回。
