# 使用与部署指南

1.6.0 默认提供**人机练习＋双手机好友 1V1**。两台手机可直接打开
[GitHub Pages 宣传主入口](https://zcinta0514.github.io/rally-badminton/) 或
[Vercel 备用入口](https://kaipai-rally.vercel.app/) 建房和加入，
无需用户电脑运行比赛服务。推荐双方连接同一 Wi-Fi，或支持设备互访的同一热点；
建房、加入时需要互联网连接。

## 双手机开始对打

1. 两台手机打开游戏，横屏游玩，并保持页面在前台。
2. 房主点「好友对打」，填写昵称、选择角色、分制和对局类型，创建房间。默认「普通对局」，也可选择「父子局」；加入者可看到房间类型。
3. 分享邀请链接或 **5 位房间码**。对方打开邀请链接，或在游戏中输码加入。
4. 两人到齐后自动开始。比赛结束后双方同意可再来一局；退出或直连中断后重新建房。

普通对局和人机正常结束后直接进入结算。只有父子局通过得分正常完赛，才会在原球场
展示双方昵称／玩家 ID，败者朝胜者跪拜一次，配合“爸爸”气泡与固定中文语音。
演出约 3 秒，不提供跳过；语音遵循静音设置。局间、暂停超时、退出和断线结算不触发。

默认使用 PeerJS 和免费的 **PeerServer Cloud** 公共配对服务，无需填写私人
API Key。公共服务帮助两台手机找到彼此，比赛随后通过 WebRTC 连接传输，
由房主手机执行规则、球路和计分。房主页面需要保持运行；公开网站创建的房间
不依赖用户电脑。

已建立的手机直连在公共配对服务断开后仍可继续，但两台手机之间的连接必须
保持可用。新建房间、加入房间需要重新联系公共服务。断开配对服务不等于可以
关闭 Wi-Fi、切换网络或关闭房主页面。

公共配对服务由第三方运营，没有本项目提供的可用性承诺；偶尔不可达时，稍后
重试或继续人机即可。本版没有随机匹配，也不承诺任意公网或热点环境都能互联。
完全没有 Wi-Fi、热点或其他通信网络时，网页无法让两台手机互相传输数据。

## 无法建房或加入时

- 先确认双方都能联网打开游戏。新建和加入都需要公共配对服务可达。
- 推荐双方连接同一 Wi-Fi 或同一热点。访客网络、AP 隔离或热点设备隔离可能
  阻止手机互访；更换允许设备互访的网络后重新建房。
- 确认房主仍停留在等待或比赛页面，房间未满，并使用当前的 5 位房间码。
- 如果提示组件版本或协议不同，双方联网刷新页面后重新创建房间。
- 比赛中直连断开时，恢复网络并重新约战。公共服务连接恢复不会自动恢复已丢失的比赛。

真实 iPhone 尚未实测；不同手机、浏览器和热点的触控、帧率与连接表现需要实机确认。

## 手机声音与观众反应

首次触碰页面后才能播放音频。从后台返回遇到无声时，再触碰页面或操作游戏即可
尝试恢复音频；已关闭的音效开关不会自行打开。静音、后台、暂停和倒计时会停止声音。

普通击球与扣杀使用不同强度的录制击球声，移动保留轻微脚步声，不播放鞋底摩擦
吱声。普通得分播放短掌声；扣杀合法落地得分，或至少 8 拍（含发球）的合法落地
得分，会配合短欢呼及少量观众抬臂、前倾。回到发球或进入新对局时清理剩余反应。

## 本机战绩与身份

默认榜单是**本机好友战绩**，只统计当前浏览器参加的最近 500 场完整好友对局，
按胜场、胜率、累计得分排序，最多显示 50 位球友。正常暂停平局计入场次和得分；
人机练习、中途退出和断线弃赛不计入。双方本机榜可能不同，因为各自参加过的
对局不同。这些记录与旧版 Node 服务器榜单独立，不属于全球榜或服务器核验战绩。

昵称和匿名玩家身份保存在浏览器中，改名保留身份。换设备、换网站地址或清除
网站数据不会自动恢复旧身份和战绩，同名也不会合并身份。浏览器阻止保存时，
页面会说明使用临时战绩，关闭后新增记录会丢失。

## 本地网页服务

开发电脑安装 Node.js 22 或更新版本，在项目目录执行：

```sh
npm ci
npm start
```

电脑打开 `http://localhost:3000/`。手机可打开启动终端显示的局域网网址，
手机上的 `localhost` 指向手机自身。防火墙应允许当前网络访问网页服务端口。

`npm start` 默认启用 `peerMode`：Node 提供本地网页资源，前端使用相同的公共
配对服务和手机 WebRTC 对打流程，比赛由房主设备执行。访问或重新加载本地网址
仍需要电脑提供网页。日常游玩可直接使用上方公开入口，无需启动这个本地服务。

## 旧版 Node 房间模式

需要保留旧版电脑主持比赛、WebSocket 同步和服务器排行榜时，显式设置
`PUBLIC_PEER_MODE=0` 后启动。

PowerShell：

```powershell
$env:PUBLIC_PEER_MODE = '0'
npm start
```

macOS / Linux：

```sh
PUBLIC_PEER_MODE=0 npm start
```

该模式下，两位玩家和主机电脑连接同一 Wi-Fi 或允许设备互访的热点，都打开
主机提供的同一个网址，一人建房，另一人输码加入。主机电脑和游戏服务需要
全程运行。房间码仅在创建它的 Node 服务中有效，不能混用默认手机直连房间码；
主机重启后房间失效，需要重新创建。

旧模式的排行榜保存在服务器，默认使用 `data/leaderboard.json`，正常重启后
可以保留。使用可写的持久磁盘并按需备份该文件；不要上传公开仓库。服务器榜
不会自动导入手机直连模式的本机榜。

恢复默认手机直连时，将 `PUBLIC_PEER_MODE` 设为 `1` 或移除该环境变量，
然后重启服务。

## 静态网站构建、GitHub Pages 与 Vercel

执行 `npm ci` 和 `npm run build` 导出 `dist/` 静态包，包含 Three.js、PeerJS
及离线资源，包括 6 个录制音效、1 个固定赛后合成语音，及各自的
`src/audio/LICENSE.txt` 与 `src/audio/FINALE-VOICE.txt` 来源说明。默认启用手机直连，
静态主机只需提供网页文件，无需运行 Node 比赛服务。

仓库自带 `.github/workflows/pages.yml`。在仓库 Settings → Pages 选择 GitHub
Actions 后，推送 `main` 会按工作流执行测试、构建和发布。工作流只上传 `dist/`，
不上传服务器数据或环境配置。

现有 Vercel 项目已连接 GitHub 仓库，生产环境跟踪 `main`；根目录 `vercel.json`
提供安装、测试、构建及响应头配置，具体流程见 [公开网站说明](PUBLIC-WEBSITE.md)。两处产物
应对应同一发布提交，分别使用各自路径配置。1.4.0 使用
[v1.4.0 标签](https://github.com/zcinta0514/rally-badminton/tree/v1.4.0) 作为发布标识。

手动构建项目子路径时，设置以下环境变量后执行 `npm run build`：

```ini
PUBLIC_BASE_PATH=/rally-badminton/
PUBLIC_PEER_MODE=1
PUBLIC_DEMO_MODE=0
PUBLIC_WS_URL=
```

Vercel 使用相同配置，仅将 `PUBLIC_BASE_PATH` 改为 `/`。两处均设置
`PUBLIC_PEER_MODE=1`、`PUBLIC_DEMO_MODE=0`，且不填写 `PUBLIC_WS_URL`。
构建脚本会重新创建 `dist/`，避免混入旧资源或错误路径。Vercel 还需将
`deploy/vercel-static.json` 复制为 `dist/vercel.json`。

默认路径是 `/`，子路径须以 `/` 开始和结束。`PUBLIC_PEER_MODE=1` 提供手机直连
和本机榜；设置为 `0` 才使用旧版 Node 前端。`PUBLIC_DEMO_MODE=1` 是兼容旧版
静态人机入口的选项，仅在手机直连关闭时限制为人机模式。Service Worker、
manifest 和资源清单均限定当前应用路径。

## HTTPS、离线人机与环境配置

两个公开入口均使用 HTTPS，可在完整资源缓存就绪后离线练习人机和播放已缓存的
录制音效。也可配置自己的可信 HTTPS 入口。离线资源不会代替建房、加入所需的
网络配对服务。

iPhone 可在 Safari 的分享菜单中添加到主屏幕。首次联网等到「离线人机已就绪」
后再离线使用。新版资源备好后，结束比赛并关闭全部游戏标签页与主屏幕窗口，
再打开启用更新；不会在对局中强制刷新。这些操作仍需在目标 iPhone 上确认。

仓库保留 `deploy/rally.env.example` 和 `deploy/nginx.conf.example`。自行配置
HTTPS 时使用有效证书，并按实际情况将 Nginx 代理到同机 Node 网页服务。
使用旧版 Node 房间时，让 `ALLOWED_ORIGINS` 与实际页面来源一致；页面和比赛
服务分开部署时配置对应的 `PUBLIC_WS_URL`。真实配置、私钥和证书不要提交仓库，
也不要放入浏览器可以下载的资源目录。

`npm start` 不会自动读取 `.env`。需要环境文件时，复制示例并设置实际值，再运行：

```sh
node --env-file=.env server/index.js
```

| 配置 | 用途 |
| --- | --- |
| `PUBLIC_PEER_MODE` | 默认 `1` 使用手机直连；`0` 使用旧版 Node 房间和服务器榜单 |
| `HOST` | 本地网页服务默认监听 `0.0.0.0`；Nginx 同机代理时可设为 `127.0.0.1` |
| `PORT=3000` | Node 网页服务端口 |
| `ALLOWED_ORIGINS` | 旧版 Node 模式允许的完整网页来源，逗号分隔，不带结尾斜杠或通配符 |
| `ALLOW_MISSING_ORIGIN=0` | 旧版 Node 模式仅允许带有效来源的浏览器连接 |
| `LEADERBOARD_PATH` | 旧版服务器榜单的持久存储位置，默认 `data/leaderboard.json` |
| `PUBLIC_WS_URL` | 旧版 Node 模式默认留空，使用当前网页所在服务；分离部署时填写对应的 `wss://` 地址 |
| `TLS_KEY_PATH` / `TLS_CERT_PATH` | 可选直接 Node HTTPS，私钥与证书路径需同时设置 |

这些服务器配置不会改变默认公开入口的公共手机配对流程。
