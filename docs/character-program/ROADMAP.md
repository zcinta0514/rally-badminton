## 如何拆任务

- 每张任务卡只交付一个能独立检查的结果，例如“挥拍时肩部形变稳定”“脚底支撑不滑动”“跨步接吊球衔接”。
- CHAR-00 使用已有详细计划；后续阶段进入前依据实际样片结果再写具体实现任务，不能预先假造未知算法和文件接口。
- 各阶段可包含多轮试验。每轮保存输入、参数、代码／资产指纹、对照结果、失败理由。
- 一个方案修正两轮后仍有同一种根本错误，应重新评估输入或方法，不无上限调参数。此为路线检查触发点，不是强制停止质量改进。
- 不用多角色数量、骨骼数量、模型面数、token 数或动捕工具数量代替质量进度。

## 推荐技术分层

1. 比赛状态：沿用权威移动、触球位置、触球时间、动作事件和暂停时钟。
2. 动作选择与混合：按准备／移动／击球／落地／恢复选择片段，处理方向与过渡；同一骨骼不可同时被两个驱动器互相覆盖。
3. 最终姿态修正：脚底支撑、球拍目标、头部观察、有限躯干与手臂补偿；不可通过拉长肢体掩盖不合理触球。
4. 人物资产：规范化骨架、蒙皮、身体、服饰、材质、角色尺寸与握拍锚点。
5. 渲染与资源生命周期：按设备档控制贴图、阴影、像素比和加载，维持人物实例间正确隔离与释放。

是否保留部分现有程序化动作、采用何种片段格式和细化骨骼，CHAR-00／01 实测后决定；旧的 18 骨骼兼容要求不能未经评估直接绑定未来全部资产。

## 回归与回退

- 先在隔离预览中并列展示旧、新人物；未验收候选不覆盖正式资产。
- 运行时迁移必须有明确的旧实现回退与资源加载失败处理，避免一个坏模型使整个比赛不可玩。
- 同一输入记录下检查旧新比赛状态一致；A 阶段不因动画改变得分、接球范围或移动数值。
- 保留发球、高远、吊球、杀球、现有扑救、赛后演出、暂停恢复、人机和好友对战；具体枚举以实施时最新基线为准。
- 合并或部署失败用可审查的回退／修复提交处理，不用强推、覆盖或伪改版本号解决。

## 时间管理

当前不预估总天数。第一轮记录素材恢复耗时、一个动作片段的制作／修正耗时、一次真机回归耗时后，给出下一阶段区间估计。每日或每次实际工作轮次结束更新进度；没有执行时不假装后台持续推进，也不创建轮询自动化。
