# RALLY 骨架与动作重建建议

2026-10-02。用户要求：骨骼和运动优先，面部次要；允许重新建模，不以成本、时间或算力筛选方案，只比较最终呈现质量。本轮为诊断与方案调查，未安装第三方工具、替换模型、采购或委托。

2026-10-03 决策更新：用户已同意按推荐方向开工，先细化最高质量动作采集。执行入口为[采集规格](MOTION-CAPTURE-SPEC.md)、[现场清单](CAPTURE-SHOOT-PLAN.md)和[质量门槛](CAPTURE-QUALITY-GATES.md)；以下调查保留原始证据与能力边界，实际进度只见 PROJECT-STATUS。方案确认不等于已采集、重建或集成第三方组件。

## 1. 结论与推荐范围

**建议重建运动人物及动作约束系统，保留比赛工程、联机、输入回放和验收体系。** 不再把现有71骨、四影响权重、旧拓扑、六段动捕或旧触点求解当作不可更改的条件。新人体可采用专业成熟底模或重新拓扑，面部保持简单；以同样的五组打球场景决定新旧路线的胜负。

不是已经证明旧网格无法修复，而是证据已证明：只继续刷权重，不能保证游戏内的最终动作质量。源动作接近通过，运行时仍有较多问题；制作骨架、约束求解、动作数据和最终变形必须一起更换或重构。

推荐主线：**专业球员完整回合采集 → 专用运动控制骨架 → 保留接触约束的重定向与动画精修 → 专项动作检索／阶段控制 → 全身可达性与支撑求解 → 最终姿态驱动身体、衣物修形 → 实际双人球场验收。**

Three.js可继续作为首个交付载体，但不把已有蒙皮和求解代码当作限制。若同一高质量母版在自定义Three运行管线达不到正常速度观感与手机交互要求，再对同样场景制作成熟游戏引擎对照；换引擎本身不能补齐错误骨架、缺失动捕和触球约束。

## 2. 当前困难：哪些已证实，哪些只是推断

基线：main／origin/main为d15ff7c，v1.7.1；有完整未提交人物成果。数字来自[权重修复检查点](ATHLETE-P1-WEIGHT-CHECKPOINT.md)，不是本轮重新跑模型得到的结果。

| 问题 | 当前证据 | 为什么继续调权重不够 |
| --- | --- | --- |
| 源动作与实际游戏不一致 | 源身体162/281→1/281；实际身体43/77→28/77；衣物／球拍31/77→29/77 | 动作混合、足地和击球IK会产生源片段未出现的新姿态 |
| 肘部体积和折叠 | 新增4帧右臂局部失败；原始部分辅助骨绑定轴有误 | 主骨姿态、骨轴、弯曲与扭转分配必须一起正确；增加骨数不等于自然变形 |
| 臂躯干碰撞 | 881→891对交叉，尚未改善 | 当前求解没有完整肩部活动域、臂躯干避碰与平衡约束 |
| 衣物跟不上身体 | 上衣穿入点4285→4616，最深32.221→35.801 mm | 源片段修形在随后IK改变身体后会失配；扩大衣服会破坏自然贴合 |
| 相对旋转绕环 | 48例两人物轨迹中4次触发0.18秒辅助骨回正 | 回正只消退辅助骨残余，不重新求合法主骨解，也不保证皮肤速度与碰撞 |
| 支撑与恢复 | 更长比赛支撑误差11.391 mm，高于10 mm门槛；全回归718/719 | 两骨IK和局部降髋不等于承重、蹬地、制动与再次启动 |
| 数据覆盖不足 | 六段真实动作主要为高远、反手平抽；触球相位用手速峰值估计 | 未同步观测的拍面、握拍、旋前旋后与真实触球无法从少量关节点可靠还原 |

本地实现核验：

- [两骨IK](../src/v4-court-motion.js)按长度和6°–150°夹角截断；持拍解评分有触点、拍面、腕部与连续性，但缺少完整人体关节域、身体避碰与支撑平衡。
- [共享可达性](../shared/v4-motion.js)主要是估计肩点及臂拍长度球体。**它可能批准人体姿态不合理的触点，但各失败中由此导致的占比尚未做消融确认。**
- [P1旋转分配](../src/p1-rotation-distribution.js)的整圈回正是明确的退化保护，不是生物力学修复。观察到的骨旋转绕环不能直接等同于真实人体某轴转了360°。
- [衣物修形制作](../scripts/correct-v4-garment-motion.py)、[运行混合](../src/athlete-v4-rigged-preview.js)和[后续姿态适配](../src/athlete-v4-court-preview.js)的顺序说明：按源片段时间驱动的修形不能覆盖全部最终姿态。

“当前解决不了”的准确边界：缺失的高速球拍／手部观测不能单靠增加算力可靠恢复；通用动作库不能提供未采集的羽毛球技术；DQS不会自动避碰；动作匹配不会创造数据库里不存在的动作；高精度换模不会修复错误的运动求解。这些问题可以通过补数据、重建约束及改变表示方式解决，不能承诺换一个插件全部消失。

## 4. 三条路线比较

| 路线 | 呈现质量的判断 | 建议 |
| --- | --- | --- |
| 保留旧骨架，继续调权重和单帧修形 | 对已知源动作有效，无法保证新触点、混合和连续回位；旧架构缺口仍在 | 只保留为对照及故障定位，不作主线 |
| 保留主体网格，重建骨架／动作／求解／修形 | 可能达到目标，前提是拓扑在相同压力测试中无明显限制 | 可并行做对照；不因既有投入强保网格 |
| 新运动员母版＋新专用绑定＋专项动捕＋全身约束与最终修形 | 最有机会系统解决当前缺口，便于统一骨轴、变形和动作设计 | **推荐主线**；根据A/B保留合格旧部件 |

选择第三条是工程判断，不是已证明的性能或画质结论。验收不通过时继续定位数据／约束／变形层，不能将换模本身当作完成。

## 5. 推荐重做架构

### 5.1 先做运动身体，脸保持简单

- 身体重点是肩带、腋窝、肘窝、前臂、手、髋、膝和踝的运动拓扑，保持比例和骨长；不先堆面部、发丝和皮肤微纹理。
- 制作控制骨架、运行运动骨架、渲染变形骨架分工明确。制作层用成熟IK/FK工具；运动层定义人体自由度、接触与关节域；变形层承担扭转分布和局部体积。不能把三层任意互换。
- 肩带包含锁骨与肩胛协同；肘屈伸与前臂旋前旋后分开，腕屈伸／尺桡偏分开；不再把整个前臂任意四元数的四分之一当作通用解剖模型。
- 脚跟、前掌、脚趾有滚动支撑，髋／膝／踝协同；双手保留可靠指骨与握拍接口。网球拍或人体通用预设不能代替羽毛球握柄标定。
- 不先锁死骨数或每点四影响。如果更多影响改善质量，就同步升级GPU蒙皮、CPU探针和QA；不能只在Blender里有效。

### 5.2 采集真实完整动作，补齐目前缺失的信息

首选专业羽毛球球员和动画／动捕制作人员合作的高质量多机位光学采集；同步记录球拍刚体、手部与高速参考视频，必要时用力台或其他接触测量校验承重。Pose2Sim等用于复核和补充，不替代未观测的真值。

覆盖发球、前场弓步、后场高远／杀球、连续平抽、防守—制动—回位；每条保留启动、引拍、触球、随挥、落地、回位及下一拍，不只截挥拍。覆盖不同触点、身位、速度、主动／被动与技术选择；精确记录时间同步、标定误差和遮挡置信度。

先做短发球、被动防守、后场击球三个最能暴露现有问题的小样。采样率、曝光和标记布局按高速球拍试采结果确定，不能仅以通用人体30/60Hz视频看起来平滑就宣称合格。

### 5.3 从可完成的全身动作出发，再形成触球

当前的“先给理想触点，表现层再把手强拉过去”应替换为：根据来球、时间、速度、支撑、身体朝向与动作库，先判断哪些动作可完成；允许补步、换技术、降低出球质量或真实漏接。

动作检索负责选合适的到位／制动／回位片段；击球采用明确的技术阶段与触球窗口。特征不只包含脚和未来轨迹，还包括拍头位置、拍面、距离触球时间、身体角速度、支撑状态、握拍和击后恢复意图。连续平抽不强制回统一ready。

全身求解同时考虑根、骨盆、躯干、肩带、肘、腕、球拍；关节活动域、臂躯干避碰、脚底接触、速度连续性是约束。关节域需随姿态变化，不能每轴固定小盒子粗暴夹角。球拍路径正确而身体不合法时，结果必须判为不可行，不靠辅助骨回正掩盖。

共享逻辑保存权威动作与触球状态，固定模拟步长；渲染插值不能改变得分与出球。网络快照同时考虑根运动、支撑、技术阶段、握拍、触球／恢复事件；模型骨姿态不直接成为依赖帧率的权威判分来源。

### 5.4 体积保持与修形必须针对最终姿态

同一母版、同一骨姿态对比LBS＋辅助骨＋修形、DQS＋修形、DDM；检查轮廓、体积、肘窝压缩、衣物关系，而非只数失败帧。DQS不是默认胜者，任何方案都要实际Three表面一致性验证。

建立多轴姿态空间修形：肩抬举×内外旋、肘屈伸×前臂旋转、腕、髋和膝踝组合。驱动来自最终约束求解后的局部解剖姿态，覆盖范围之外明确记录，补制作样本，不无界外推。

身体与服装分别制作，统一接触／变形状态；高质量离线服装模拟可作母版，再拟合骨骼、morph或动态变形器。DemBones可压缩已正确的网格动画，但对未见过的运行姿态没有自动保证。

顺序固定为：动作选择／采样 → 根与朝向、支撑约束 → 肩肘腕与球拍约束 → 合法变形骨 → 最终姿态修形／衣物修正 → 渲染。Blender驱动器与约束要烘焙或显式移植，不能依赖GLB神奇保留。

### 5.5 物理运动学习作为质量对照

既然制作算力不设限，可用ProtoMotions／MimicKit建立专项动作的受力、落地和平衡控制实验。它们可以帮助得到更可信的恢复与扰动反应，但需自有数据、人体参数、球拍模型和专项奖励约束。

不能因为用了强化学习就认为结果自然：还要验证拍面触球精度、技术风格、连续击球与不常见来球。先与专业动捕精修＋约束求解比较，只有明显提升最终画面才纳入交付。手机端通过提炼后的控制／动画表示运行，制作资源不限不等于允许游戏延迟和掉帧。

## 7. 验收标准与不能偷换的指标

- 源动作与最终运行姿态分开报告；身体、衣物、球拍、接地分开报告。计数、深度、持续时间、新增失败以及正常速度画面一起看。
- 原有触点1 cm、支撑窗口漂移5 mm等可作小样工程门槛；拍面、事件时间、关节速度与肌肉发力顺序需结合标定与专业参考定标，不冒称通用人体标准。
- 连续接触窗口检查实际蒙皮脚底，区分后跟／前掌滚动与真正滑步；不是要求任何时候整只脚全部固定。
- 对辅助骨保护、IK不可达、角速度峰值、全身碰撞求解失败全程记录。回到ready不是动作已自然；发布候选的正常五组场景不应依靠整圈回正保护。
- 针对触球、深屈肘、急停和保护触发前后加密采样并检查完整轨迹，不继续只看77个稀疏帧。真实接触与数值自交分开标注，不为追求0计数削皮或撑衣服。
- 预留没有参与权重／修形制作的来球、触点、速度、比例和衔接作验证集，检查新路线是否真正泛化。
- 最终看专业羽毛球动作的准备、蹬地、身体协同、挥拍、随挥、制动和下一拍能力；数值全过也不能替代正常速度视觉评价。
