# P1-1：运动人物样板与实际姿态变形验收

对应 [开发计划 P1-1](../DEVELOPMENT-PLAN.md)。本文件限定任务与验收；当前结果、分支、目录和下一步只看 [PROJECT-STATUS.md](../PROJECT-STATUS.md)。拆分后的小 PR 必须注明改善的具体场景，不能据此自动宣告整个 P1-1 完成。

## 目标与范围

制作比例正确的运动人物、基础服装、球拍与绑定，在实际游戏的发球、弓步、后场击球、连续平抽和制动回位中检查变形、握拍与足地关系。身体和服装自然贴合；不能通过撑大衣服、缩短球拍或降低门槛掩盖问题。

当前候选用于隔离实验。正式人物替换、专业采集采购／委托、外部服务消费和线上发布不由这份任务卡自动授权。用户已选择运动人物与动作约束重建方向，先按 [P1-3](P1-3.md) 细化采集；选定方向不代表新骨架已制作或质量已通过。

## 依赖与入口

- [开发计划](../DEVELOPMENT-PLAN.md)、[五组固定场景](../P0-SCENARIOS.md)、[共享接口](../PLAY-CONTRACT.md)。
- [P1 权重修复检查点](../ATHLETE-P1-WEIGHT-CHECKPOINT.md)：源动作与实际运行的失败分类、候选哈希及证据。
- 候选依赖本地未提交源码、模型及被忽略的 Blender 制作文件。新 clone／干净 main 不能假定已具备这些内容；迁移需按 [协作流程](../WORKFLOW.md) 保存并整理。

## 验收与复现

1. 优先正常速度完整场景，再检查慢放／关键帧；覆盖双方、连续过渡、暂停和倒带。
2. 同时检查源片段和 Three.js 混合、足地、IK 之后的真实表面；源动作改善不能代替最终姿态验收。门槛沿用开发计划。
3. 记录新增失败和改善，尤其右臂局部、臂与躯干、上衣穿入、支撑漂移和整圈回正。不能只报总失败数下降。
4. `npm test` 复现代码回归；运行时表面审计的输入清单与产物见上述检查点。历史失败不表示本次重新测试过。
5. `npm run build` 后重启正确目录的预览服务，核验浏览器实际模型和脚本。最终正常速度动作须用户观看验收，手机性能须在冻结条件下实测。

## 回退与交付

保持正式人物和冻结对照可用；候选回退用已保存的资产及对应运行时代码成组恢复，不能只替换 GLB 留下不匹配的骨架逻辑。证据保留版本与哈希。任务完成必须对应可审查差异、检查点和实际验收，不用动作数量或测试总数代替。
