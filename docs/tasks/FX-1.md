# FX-1：回合体力恢复与球员脚下体力条

这是任务规格。当前进度、失败、分支和下一步只维护在 [PROJECT-STATUS](../PROJECT-STATUS.md)，本文不另建实时进度表，也不预定发布版本号。

## 目标、范围与依赖

- 对应 [开发计划](../DEVELOPMENT-PLAN.md) FX-1、P2-4／P2-6、P3-5、P5-3。
- 问题：发球与回合共用恢复计算，分间也补体力；摇杆强度 0.15 两侧恢复量突变，左下体力不醒目；联机跨触球插值会提前显示扣费。
- 目标：体力只在回合中低强度活动时恢复，双方脚下可读，玩家能解释当前为何恢复或消耗。
- 继承最新可发布提交及实际需要的本地玩法成果。先完整保留并形成可继承提交，再建独立任务工作树；不能从干净 main 丢弃当前未提交依赖。人物资产保持现有候选与默认入口。
- 首轮保留角色上限、恢复系数、跑动／击球成本和疲劳影响；不改变球种、移动动作、计分或新增竞技模式。

## 权威体力规则

1. 新对局满体力。serve、point、intermission、paused、countdown、over 均不恢复，换分／换局不补满；发球移动和实际触球仍正常耗费。
2. rally 中取 u=max(实际水平速度／角色未疲劳基准速度，归一化摇杆强度)。连续 0.35 秒 u<0.4 且无引拍／挥拍／腾空／落地缓冲后才允许恢复。高强度动作立即清零等待，非 rally 阶段不累计且清零等待；当前片段刚进入 prepare 或实际挥拍也即时阻断。
3. 恢复率=角色 recovery × [1-smoothstep(0.1,0.4,u)]；运动消耗继续按 8.5 × 角色 runCost × 实际速度比例计算。净变化为恢复减消耗，只在净变化>0 时显示“恢复中”；u≤0.25 作为三角色稳定回补的验收场景。
4. 接地资格由共享动作时钟判断。V4 排除腾空至 landAt 以及其后 0.24 秒落地缓冲；classic 在现有动作／冷却结束前阻断。不得读取渲染骨骼决定体力。模拟片段内跨过恢复等待或回合结束事件时，只计符合条件的部分时间。
5. 体力限制在 0 与角色上限之间。保留耗尽时 65% 基础移动速度下限和合法击球能力，强攻风险仍明确反馈；不能硬锁角色导致无法继续。

## 展示、接口与联机

- 双方体力条锚定地面位置并投影到屏幕，跳跃仍留在落脚位置；己方约 76×6 像素并显示百分比，对方约 60×4 像素，均按角色上限归一化。移除左下重复体力面板，适配镜头、两端和横竖屏，避开接球圈与触控区。
- 显示恢复等待、净恢复、消耗和低体力状态；低于 25% 使用颜色及形状提示。暂停显示静态值，赛后人物互动隐藏。
- lastShotInfo 增加触球前后体力 staminaBefore／staminaAfter；球员共享状态输出净变化率、恢复等待和展示状态。源数据由比赛逻辑产生，UI 不自行计算权威体力。
- 击球方按前快照→staminaBefore、触球瞬间→staminaAfter、再→后快照分段插值；另一方正常插值。缺失多个触球时不伪造过程，同包得分按现有事件时间边界呈现。
- Node 联机、手机直连、重赛与快照校验同步更新；规则兼容版本显式检查，旧客户端不兼容时明确提示更新。
