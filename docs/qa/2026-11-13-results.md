# 结算画面整理

基线：远端 main `32d35a49657e6bfa53035e822f32c122b069a15b`（1.21.1），通过 GitHub API 核对。独立分支 `codex/result-screen`，保留三个击球键的已发布恢复样式。版本 1.21.2，构建 `9a8cd081973e0ff7`。

用户确认按横屏布局、胜负、双方比分和再战入口的方向整体整理。

## 设计与范围

- 横屏采用左侧比赛结果、右侧赛后操作，竖屏改为上下排列；淡线分隔，无完整弹窗外框、无按钮外框。
- 双方名称与各自分数对齐，当前玩家所在队始终在左侧。胜者分数用浅绿色标记，未分胜负不标记胜者。
- 标准赛主数字为最终局数，说明保留最后一局比分，标题使用“本场”；快速赛和挑战保留原本胜负逻辑。
- 再战、排行榜、战绩状态与回首页沿用原事件处理。只调整结算展示，不改计分、网络协议或玩法。

## 验证

- Windows Chrome 手机/触摸模拟，844×390、667×375、568×320、390×844：普通结算无溢出或滚动，主要按钮高度至少 44px。
- `scripts/verify-results.mjs`：在浏览器网络响应中临时注入结束场景，调用生产 `finishMatch` 后执行真实展示流程；测试钩子不进入生产源码。验证双打再战、标准赛局数/分数区分、回首页、挑战失败及再次挑战入口；额外以长名称和全部联机操作做展示压力测试。零页面异常。未进行真机或 iOS Simulator 测试。
- `tests/connection-recovery.test.js`：49 项通过，新增双打/标准赛/未分胜负结束和客队玩家比分方向检查，保留排行榜返回、断线及再战回归。
- Windows 回归 851 项通过，0 失败；运行时按已有环境限制排除名称匹配 `symlink escape|equivalent symlink worktree` 的符号链接用例。GitHub CI 负责 Linux 无排除测试。
- `npm run build` 通过。
- 本地服务从当前独立目录重启，http://localhost:3384 的版本和构建号已核验。截图和可重复报告位于 `artifacts/results/`。
