## 五、可复用技术与禁止回退

V3 的 `scripts/v3_garment_loft.py`、截面环带放样、人体外包络采样、KDTree 最近邻权重传递、穿透 QA 和边界条带生成可作为技术参考，但不能直接把 V3 网格复制到 V4。V4 人体比例、面集和阶段合同不同，应建立 V4 专用参数和测试。

禁止把 V3 旧 `fitted_shell` 面集抽取服装当作 V4 正式方案。该路径已经反复出现贴体、侧面膨胀、下摆锯齿、肩袖断裂和动作权重硬伤。V4 球衣、短裤和鞋必须是独立对象、独立拓扑、可单独替换的阶段资产。

布料模拟不是第一步。先完成确定性的静态轮廓、间隙和穿透检查，再决定是否为褶皱做短程模拟。V3 已验证 headless Cloth 会拉坏球衣平整度并让短裤裆部自相交；未经拓扑修复，不要直接启用旧模拟参数。

## 六、侧边栏与验证规则

项目 Node 服务启动时会构建资源快照。源码或 GLB 更新后必须重启服务；只刷新页面不能证明加载的是新资产。Service Worker 和旧标签可能继续保留旧缓存。

每个新服装候选至少完成：

1. 重建 GLB，并记录大小和 SHA-256。
2. 渲染正面、侧面、背面，服装阶段建议再加 3/4 正面和 3/4 背面。
3. 运行 V4 Clothing 专项测试和 `npm run build`。
4. 启动新的本地预览服务，更新 URL 的 `rev=`。
5. 清理侧边栏页面 Service Worker/Cache 后重新导航。
6. 在页面内 fetch `/src/models/athlete-v4-clothing.glb`，用 `crypto.subtle.digest` 核对实际字节数和 SHA-256。
7. 确认静态检查点的动作、进度条和配色按钮仍保持禁用。

本地预览、工作区源码、已推送源码和线上部署是四种不同状态，交接和汇报必须分开陈述。
