## 二、全新 Blender 制作方法

1. 建立独立、可编辑的新 .blend；导入上述 CC0 人体基底，在其独立网格上重新塑造比例和细节、重新绑定新骨架并建立原创动作集合，不要求抛弃合法来源的基础人体拓扑。用新人物的比例 blockout 验证重心和握拍接触，再细化手、面部和运动服。**不得以旧 V2 关键姿势开始微调。** Blender 本地以米计、+Z 向上；导出 glTF 后验证引擎坐标轴转换，不假定两端轴向相同。
2. 控制骨至少包括 root_motion、pelvis、spine_lower、chest、neck/head、双侧 clavicle/upper_arm/forearm/hand 和 thigh/shin/foot/toe；持拍侧另有 forearm_twist、手掌轴、独立握柄和拍面接触锚点，拇指、食指及其余手指成组可辨。肩旋转、肘屈伸、前臂轴向旋转分别驱动，不能只靠腕骨折叠模拟杀球；另一手承担平衡。
3. 新制作 ready/split_step、overhead_smash、overhead_clear、overhead_drop、front_lunge、recover_center 六类片段。高远球、吊球与杀球可共享预判视觉规律，必须另画各自拍面、速度峰和随挥曲线，不能仅把一套杀球动画变速。左右跨步分别绘制，禁止负缩放镜像整个人物以免反转握拍、布片和法线。
4. 以脚掌接地标记和双足 IK/足底约束驱动：支撑期锁定鞋底世界位姿，离地释放并有脚尖滚动；落地髋/膝/踝共同缓冲。root 位置顺应脚部真实步幅，不平移整个人物伪造脚步。球拍为握柄局部锚点子对象；拍面接触必须与现有比赛接触事件对齐，**角色动画绝不覆盖出界、触网或计分规则**。
5. 髋/胸先预旋再加速，肩部内旋、伸肘、前臂轴向调整拍面、适度腕部与握力协同随后接续，避免所有关节同帧达到峰值、腕关节“甩断”、拍子穿头。原论文只讨论躯干、肩、肘、腕的大段时序；前臂旋前与握拍细节是独立待视频/教练资料核验的 rig 设计，不能声称论文给出了个人旋前数值。
6. 为 idle → split → move → prepare → contact → follow → recover 设独立事件标记。游戏触球可重定时角色接触帧，但不可抹掉足底锁定、球拍拍面与随挥轨迹。侧边栏能够暂停、慢放、逐帧拖动及切换正、侧、背、3/4 视图。

## 三、验收标准与不合格项

- **证据**：Commons 已实看记录与 BWF 未实看槽位必须分开；只有实际看见 BWF 官方比赛画面，才填写 BWF 专属记录栏的 mm:ss，注明是否连续镜头、机位、是否慢动作。论文图、网页标题、搜索结果、缩略图都不等于视频逐帧观察；看不到就标“未观看”。用户可提供有权使用的参考影像，或等待官方片段恢复播放后修订。
- **运动**：逐帧检查六类动作。杀球须辨认分腿→移位→髋/躯干蓄势→引拍/肘领先→肩肘前臂的拍面加速→击球→随挥→回位的可读先后；前场跨步作为独立支线，不强迫每一拍都演同一固定连招。正、侧、背、3/4 四视角下无拍面瞬移、肩/肘/腕反折、拍子穿脸或球衣穿模。
- **接地/击球**：按动画使用的米制单位统计支撑脚锁定期世界位移，项目 QA 首轮目标每次接地滑移 ≤ 0.02 m（**自定视觉阈值，不是论文的生理值**）；击球事件帧拍面与羽毛球在场地三维深度和朝向上吻合；跨步前脚清楚制动、后推回位有力量传递。不能靠挥拍穿球掩盖接触系统误差。
- **预览/集成**：侧栏六类动作反复切换、循环、暂停/拖动无 NaN、骨骼抖动、落地后 root 突然重置；球拍握柄不脱手。检查 GLB 骨名/权重/片段和项目测试、构建，不影响比赛命中、失误及计分。服务构建资源快照：源码更新后重启本地服务，核查实际服务目录和浏览器加载画面/功能；本地预览、已推送源码、线上部署分别报告。
- **分级交付**：第一轮为侧栏可调整的动作 animatic；第二轮须通过脚底、拍面、肩肘及衣袖变形；第三轮为游戏节奏、画面轮廓和目标设备性能。每一级均需四视角和逐帧记录，单张静态角色图或“构建通过”都不能宣称高精人物动作完成。

以上帧数、滑移目标、接触标记均属 RALLY 制作与 QA 初稿；不得冒称 BWF 官方规则、论文测量值或石宇奇个人动作参数。
